# 自架模型推論服務

## 專案概覽

這套服務把自架模型的權重管理、推論介面和部署流程集中起來，供不同應用共用。應用透過一致的 HTTP 介面取得模型輸出，並自行管理領域提示詞、工具執行、人工校正與產品驗證。見 [專案說明](../README.md)與[架構責任](architecture.md#責任)。

## 使用流程

維運者先註冊指定修訂版本的模型權重，選定 vLLM 或 Transformers 後啟動服務。應用先確認健康狀態，再從模型清單讀取實際能力，依支援項目送出一般 JSON 呼叫或串流請求。工具及媒體輸入取決於使用中的後端與設定。見 [本機使用指南](local-use.md)與[用戶端接入流程](client-integration.md#最小接入流程)。

## 系統架構

固定部署模式由 CPU API 接收和驗證請求，再轉交 Docker 內的 GPU 執行端。vLLM 和 Transformers 各自使用獨立的執行環境，模型權重唯讀掛載。API 限制同時執行量，請求逾時或用戶斷線後仍追蹤底層運算，直到可以確認完成。另有明確啟用的單機排程模式，使用 SQLite 保存工作，讓控制端與執行端可獨立恢復。見 [執行生命週期](architecture.md)與[單機排程](scheduler.md)。

## 實作與貢獻

專案實作模型註冊與固定版本部署、能力查詢、串流完成確認與故障恢復。單機排程將提交識別碼和工作綁定。即使首次回應遺失，應用仍可用原識別碼查回工作 ID，再查狀態或結果，避免盲目重新送出。見 [接入契約](client-integration.md)與[排程 API](scheduler.md#api)。

## 成果與限制

Linux 原生 Docker 的 0.2.0 固定映像曾通過真實 GPU 驗收，涵蓋 vLLM 的文字、圖片、工具與合成影片，以及 Transformers 的文字推論。該次也有 117 項 CPU 契約測試。其後另有單台 Linux RTX 4090 的排程工程驗收，涵蓋模型切換與資源回收。各應用的輸出品質和其他 GPU 環境的相容性仍需個別驗證。見 [Linux 原生 Docker 驗收摘要](acceptance.md#linux-原生-docker-驗收摘要)與[單機排程實機證據](../evidence/2026-09-23-linux-managed/README.md)。
